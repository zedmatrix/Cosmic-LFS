1.1. Preparing Cosmic

COSMIC is a Wayland desktop environment, so no Xorg server is required. Before building the packages in this chapter, make sure the following are installed and working: a recent Rust toolchain, Mesa (with GBM and EGL), libinput, libxkbcommon, Linux-PAM, D-Bus, polkit, and systemd (or another seat manager such as seatd). Each COSMIC package is a standalone Cargo project with vendored crates, so the packages can be built in any order.

1.1.1. Extraction Method

The source tarballs are compressed with zstd using a 2 GB long-distance window. The zstd default limit is 128 MB, so decompression needs an extra option and about 2 GB of free RAM: 

tar --use-compress-program="zstd -d --long=31" \
        -xf ../archive-name.tar.zst

Without the option, tar fails with Frame requires too much memory for decoding.

1.1.2. Building with Cargo

The tarballs include a vendor directory, so the builds work offline. Use --frozen (or --offline --locked) so Cargo doesn't try to reach the network or change Cargo.lock.

1.1.3. Workaround for packages using atspi-common

Some packages vendor the atspi-common crate, whose validate macro needs to be told where its D-Bus XML files are. Run this from the top of the source tree, before building: 

export LOCKSTEP_XML_PATH=$(pwd)/vendor/atspi-common/xml

Run unset LOCKSTEP_XML_PATH after the build so the variable doesn't affect other packages.

1.1.4. Rendering in a Virtual Machine

In a virtual machine without GPU acceleration, the wgpu renderer may fail with a shader validation error. If so, create /etc/environment.d/50-cosmic-render.conf as the root user: 

cat > /etc/environment.d/50-cosmic-render.conf << "EOF"
        WGPU_BACKEND=gl
          LIBGL_ALWAYS_SOFTWARE=1
          GALLIUM_DRIVER=llvmpipe
          LANG=en_US.UTF-8
        EOF
